# 设计说明

本文只记录插件的设计边界、关键取舍和不变量。安装、配置、使用、隐私与 HTTP 契约见 [README](../README.md)。

## 1. 目标

让「不指定工作区」成为一种一等的新对话方式：

- 新对话页的工作区菜单里可以直接选它；
- 为这次对话创建一个以真实 session id 命名的独立文件夹；
- 该文件夹同时是会话的 `cwd` 与 `workspace-write` 沙盒边界；
- 输入、发送、消息、标题、归档都走 DSH 原生路径；
- 首条消息发出后，临时工作区消失，对话落进侧栏原生的「未分组」。

## 2. 非目标

- 不替代或改造 DSH 的工作区机制；
- 不新增模型工具，不代理、不读取、不改写消息内容；
- 不修改 DSH 的既有配置或会话日志（设置页只写本插件自己的行配置）；
- 不接管输入区，不伪造未分组分组，不硬删除文件。

## 3. 状态模型

| 状态 | 会话 | 工作区登记 | 侧栏 | 沙盒边界 |
| --- | --- | --- | --- | --- |
| 空闲 | 无 | 无 | 不变 | — |
| 暂存 | 已创建、空白、无消息 | 临时登记，标题为「不指定工作区」 | 顶部临时分组 + New Session | `<工作路径>/session-<uuid>` |
| 落定 | 同一会话，已有首轮 | 已撤销 | 「未分组」普通行 + 文件夹标记 | 同一文件夹 |
| 放弃 | 空白会话被归档 | 已撤销 | 分组与 New Session 消失 | 空目录进入废纸篓（可关闭） |

暂存是唯一有妥协的状态：侧栏顶部会多一个临时分组。它在首条消息发出、用户切走或插件清扫后消失。

## 4. 关键取舍

### 4.1 文件夹在点击时创建，而不是发送时

DSH 中可输入的空白会话必须挂在真实工作区下，工作区路径必须是已存在目录，会话的 `cwd` 创建后不可变。因此只能在点击「不指定工作区」时就把目录、临时工作区和空白会话建好。

代价是点击即产生目录；收益是输入区从第一刻起就是原生可用的，沙盒边界也从第一刻起确定。

### 4.2 暂存期使用临时工作区

空白会话不能脱离工作区存在，而 DSH 的侧栏没有「置顶但不属于任何分组」的位置。插件因此在点击时登记一个临时工作区，让侧栏出现一个临时分组；发送后立即删除登记，会话就落入原生「未分组」。

不采用的做法：整体替换 `sidebar.workspaces` 槽位，或注入针对宿主类名的全局样式。两者都会把插件的稳定性绑到侧栏内部结构上，超出插件边界。

### 4.2.1 落定后的顺序

DSH 的「手动排序」把从未见过的成员追加到已保存顺序的末尾。会话在临时工作区撤销的瞬间才第一次成为「未分组」成员，因此会被排到已有会话之后；原生空白会话不会，因为它在创建时就已属于目标分组并被置顶写回。

插件在 `/settle` 成功、且浏览器快照已不再把该会话归入任何工作区之后，调用 `uiWorkspace.pinSession()`：DSH 会在 Host 置顶后用自己的顺序写入把它领到所在账号（「未分组」）与平铺列表的最前；紧接着 `uiWorkspace.unpinSession()` 只取消置顶，已保存位置保留。已置顶、已归档、接口缺失时整步跳过，任何失败只记日志，不影响落定本身。

### 4.3 删除 = 归档 + 系统废纸篓

DSH 没有永久删除会话的 API，只有归档。插件把「删除」定义成组合动作：

1. 归档会话（可恢复）；
2. 撤销可能残留的临时工作区登记；
3. 把文件夹移入系统废纸篓。

运行中的会话先拒绝，确认后才停止并归档。废纸篓不可用时只归档并引导手动处理，绝不退化为硬删除。

### 4.4 包装 `startSession`，而不是新增入口

DSH 没有为「新建会话」提供插槽：侧栏、标题栏和 `session.new` 命令最终都调用 `uiWorkspace.startSession`。插件在客户端包装这个方法，只处理「没有显式工作区、也没有初始内容参数」的调用；显式工作区、带 `prompt` / `clearPreviousDraft` 的调用原样透传。

这样既能记住上一次选择，又不会把正在普通工作区里的人拽进临时空间。任何异常都回退到原方法。

## 5. 模块边界

| 部分 | 职责 | 不做什么 |
| --- | --- | --- |
| `index.js`（Host） | 创建目录、登记/撤销工作区、收尾、清扫、清单、废纸篓、配置写入 | 不读消息内容，不绕过 DSH 服务直接改会话 |
| `client.js`（Browser） | 菜单、设置页、行标记、`startSession` 包装 | 不碰文件系统，不发远程请求 |

浏览器只通过同源 `POST /api/session-autospace/*` 与 Host 通信。所有路由先过 DSH 的同源 admission fence，再解析 JSON；成功返回 `{ok:true, value}`，失败返回 `{ok:false, code, message}`。

## 6. 数据与不变量

```text
<工作路径>/
  session-<uuid>/            # 会话 cwd + 沙盒边界；创建时 mode 0700
$DSH_HOME/session-autospace/
  last-pick-<profile>.json   # 上一次选择；mode 0600，原子写
```

- 目录基名必须严格等于 session id（`session-<uuid>`），不接受其他名字。
- 目录必须位于 `realpath(root)` 之下，且不是符号链接。
- 会话的 `header.cwd` 必须等于该目录的 `realpath`。
- 会话日志仍由 DSH 保存在自己的 `$DSH_HOME/sessions/...` 下。
- 记忆文件只保存 `{version, kind, at}`，不保存标题、路径或对话内容。
- 只有「目录为空 + 会话仍空白」时，自动回收才会把目录移入废纸篓；有内容时只归档。

## 7. 安全模型

- 工作路径：绝对路径、无 NUL、`mkdir -p` 后 `realpath` 稳定、可写。
- 请求：`POST` JSON、body ≤ 64 KiB、操作白名单、标题 ≤ 200 字符、批量 ≤ 100 条。
- 所有路径和会话校验在 Host 侧完成；浏览器传来的路径只作为候选值。
- 错误只回显相对信息，不回显其他路径。
- 插件不发起远程请求，没有遥测；界面只使用宿主设计令牌和本地资源。

## 8. 兼容性策略

不设精确版本门禁，不把 `@deepseek-ai/*` 写进 `peerDependencies`，运行时按能力探测：

| 缺失能力 | 降级行为 |
| --- | --- |
| `webServer` / `connection` | 路由不注册，菜单入口置灰并说明原因 |
| `configEditor` | 设置页只读，开关置灰 |
| 系统废纸篓 | 删除置灰，保留归档并引导「在访达中显示」 |
| `session/event` | 由客户端 blank 观测和激活清扫收尾 |
| `retainInfo` | 关闭「切换走自动消失」，改用激活清扫 |
| `uiWorkspace` / `startSession` 变化 | 不安装包装，保留 DSH 原行为 |

槽位契约变化时插件选择不渲染并记日志，而不是让宿主菜单一起失效。

## 9. 已知限制

- 暂存期侧栏会多一个临时分组；这是空白会话必须挂在真实工作区下的直接结果。
- 文件夹在点击时创建，无法延迟到发送。
- 删除只有「归档 + 废纸篓」的组合语义。
- 记忆按 profile 保存，不跨机器同步。
- 替换菜单依赖 `conversation.hero.workspace` 的 owner props 形状；大版本变化时退化为不渲染。
